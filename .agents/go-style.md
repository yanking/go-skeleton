# 编码规范

> 三部分:**硬规则**是本仓库自己的决定,与通用惯例冲突时以硬规则优先;**通用惯例**归纳自 Google Go Style Guide,已写成可直接执行的条目;**proto 注释**是 proto 契约的注释写法,硬规则 3 与「通用惯例·注释」对 proto 不适用。

## 硬规则

1. 每次改动完成后运行 `gofmt -w .`,提交前 `gofmt -l .` 必须无输出;其余提交门槛见宪法第 5 条。目录与文件名一律 snake_case;包名按「通用惯例·命名」。
2. 注释与面向用户的错误消息用中文;注释讲为什么,代码自己能表达的不写。
3. Go 导出项必须有以标识符名开头的 doc 注释。「导出项」指**包级 API**——导出的类型、函数、导出类型上的方法、常量与变量;未导出类型上为实现第三方接口而写的方法(如桥接 GORM / asynq logger 的 `Info`、`Trace`)进不了 godoc,不在此列,只在有取舍要交代时才注释;同组常量/变量可用一条组级注释覆盖。proto 注释按「proto 注释」一节。
4. 错误:就地处理或立即返回;包装用 `%w` 靠近根因包一次;判断用 `errors.Is/As`;业务错误码约定见宪法第 2 条与 AGENTS.md「错误处理约定」。
5. 日志只用 `slog` 结构化键值对。例外:适配第三方日志接口(如 `pkg/mysql`、`pkg/pgsql` 桥接 GORM logger)时按其 `Printf` 式签名格式化。
6. 接口在使用方声明、保持小;依赖显式注入,无全局单例。现存唯一例外是 `pkg/log`——`New` 同时 `slog.SetDefault`,好让第三方库经 slog 打的日志也走同一出口;取舍与还原方式见其包注释。再开例外须同样在包注释里写明代价。
7. 测试:表驱动、标准库断言、手写 mock。
8. 第三方依赖:标准库优先,引入需说明不可替代的理由。
9. 封装前先查 `pkg/`:已有则复用;通用能力按领域命名沉到 `pkg/`(如 `pkg/errcode`)。
10. 命名不复述包名:包名在使用处已限定一次,文件名与类型名再带一遍即 stutter。判据是「删掉与包名同词的部分后,剩下的是否仍是完整且有区分度的名字」:是则删(`redis.DB`、`errcode.Code`);删后空泛则保留(`config.Config`、`telemetry.Telemetry`,及与包同名的主文件 `errcode/errcode.go`)。

## 通用惯例(归纳自 Google Go Style Guide,写码照此执行)

**命名**
- 包名全小写、无下划线、短而表意;目录名仍按硬规则 1 用 snake_case。
- 导出名用 MixedCaps,缩写词整体大小写一致:`URL`、`ID`、`ClientIP`。
- 读值方法名即字段名 `Foo()`,赋值方法 `SetFoo()`。
- 单方法接口用动词 + er(`Extractor`)。

**注释**
- 导出项 doc 注释是完整句子,讲清用途、约束与为什么。
- 包注释放主文件顶部(与包同名文件或 `doc.go`):一句话说明包提供什么、何时使用。

**导入**
- 标准库 / 第三方 / 本仓库三组,组内字母序;仅包名冲突时起别名(如 `goredis`)。

**控制流**
- 主路径左对齐:错误与边界条件先返回,正常逻辑保持顶层缩进。
- 取值与判断合并:`if v, ok := m[k]; ok { ... }`;循环写 `for i := range xs`,未用的下标用 `_`。

**语言**
- 空接口写 `any`。
- 每个类型固定一个短 receiver 名(`c *Client`)且全部方法一致;同一类型的值/指针 receiver 择一而终。
- 跨调用边界的函数首个参数 `context.Context`。
- 切片零值即空切片:`var xs []T` 声明后直接 append。

**结构**
- 函数收接口、返具体类型;接口按使用方需要组合,保持单一职责。

## proto 注释

proto 是对外契约,注释经 `make proto` 直接生成 OpenAPI 的 `summary` / `description`,读者是 API 消费者,写法对齐 googleapis:

1. **不以标识符名开头**:写 `// 创建用户`,不写 `// CreateUser 创建用户`。message、service 同理。
2. **rpc 注释首行简述、空行、再详述**——生成器据此拆 `summary` 与 `description`。首行是文档页的操作标题,故不带句末句号,也不塞分号从句:

   ```protobuf
   // 创建用户
   //
   // name/email 为空返回参数错误(10001)。
   rpc CreateUser(CreateUserRequest) returns (User) { ... }
   ```

3. **message 与字段逐个注释**,写在上方独立注释块。字段漏注释,文档页该字段就是空白。
4. 除 rpc 首行外,描述性文字按正常中文句子书写,带句末句号。
